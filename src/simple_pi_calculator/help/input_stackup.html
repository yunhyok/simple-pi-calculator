Input: Stack-up Excel file

The stack-up describes every layer of the board or substrate from top to bottom: copper layers (metal) and the dielectrics between them. It is imported from an .xlsx file in the Stack-up tab (Import…) or with File ▸ Import ▸ Stack-up…. The imported table is stored inside the project, so the project still opens if the Excel file is moved; Re-import reads the file again after you changed it.

How headers are recognised

Header texts are matched tolerantly, so files from different CAM tools usually import without editing:

  1. Sheet: the first sheet whose name contains stack; otherwise the sheet that was active when the file was saved. If that sheet has no recognisable header row (e.g. a cover or notes sheet), the other sheets are tried in workbook order.
  2. Header row: rows 1 to 20 are scanned; the header row is the first row in which all required columns are found. Title rows above the header are therefore allowed.
  3. Normalisation: each header cell is converted to lower case; µ/μ becomes u, δ becomes d, ε becomes e; spaces, underscores, dots and other punctuation are removed; text in ( ) or [ ] is taken as the unit. Example: Thickness (mm) → name thickness, unit mm; tan δ → tand; Layer No. → layerno.
  4. Matching order: Layer name is tested first (so that "Layer Name" is not taken as the layer number), then Layer number, Thickness, Conductivity, Dk, Df. Each header cell is used for one field only. If two cells match the same field, the second one is ignored with W_XL_DUP_COLUMN.
  5. Data rows: all rows below the header; completely empty rows are skipped; reading stops at the first row where all required cells are empty. Merged cells count as if every cell of the merged range held the value (e.g. one PWR name merged over several decap rows).

Numeric cells may be real numbers or text such as "5.8E7" or "0,035" (a comma is read as decimal point). Formula cells are accepted if Excel stored their calculated value; files produced by scripts without a cached value give E_XL_FORMULA_NO_VALUE – open and save the file once in Excel.

Metal or dielectric?

The Conductivity cell alone decides the layer type:

  • a number greater than 0 → Metal (a plane or signal layer; Dk/Df in the same row are ignored);
  • empty, 0, - or n/a → Dielectric (Dk is required, Df recommended).

Check the Type column after import. A dielectric row with a conductivity value by mistake becomes a metal layer, and the PWR/GND pair around it will be reported as having a metal layer in between.

What is derived from the stack-up

For each PWR net the layers strictly between the PWR layer and its GND layer form the cavity dielectric:

d        = sum of the thicknesses of all layers between PWR and GND
εr_eff   = series combination of the dielectric layers (layers stacked in the field direction)
tanδ_eff = matching effective loss tangent

Example: 0.05 mm with εr 4.0 / tanδ 0.020 plus 0.05 mm with εr 3.5 / tanδ 0.010 → d = 0.1 mm, εr_eff = 3.733, tanδ_eff = 0.0147. With a single dielectric (example: VDD_CORE, layer 4) the values are simply d = 0.1 mm, εr = 4.3, tanδ = 0.018.

The via length uses the depth of the nearer plane below the Top surface (z_top column), see Via length. The conductivity and thickness of the PWR and GND layers determine the conductor loss of the planes (skin effect).

Common mistakes

  • Thickness in µm without unit: 35 in a column called Thickness is read as 35 mm. Write Thickness (um) in the header.
  • Df in percent: 2 instead of 0.02 gives E_STACK_DF.
  • Solder mask or plating rows with a conductivity: they become metal layers. Leave conductivity empty for non-copper rows, or remove them (they do not affect the plane pair anyway).
  • Bottom-up numbering: layer 1 must be the Top side, where decaps and the PAD are mounted.
  • Merged header cells across two rows: put each header in one cell of one row.
