Troubleshooting and message codes

Sections: Reading messages · Common problems · Code index · Log file

Reading messages

Every problem found while importing, validating or computing appears in the Messages dock with:

  • Severity – E_… error: the affected item (file import, or one PWR net) is not computed; W_… warning: the result is computed but may be less accurate or not what you intended; I_… information.
  • Code – a stable identifier; look it up in the code index below.
  • Source and location – file name with sheet cell (Stackup!C7) or line number, or PWR:VDD_CORE.

Double-click a message to jump to the related tab and row. Table cells with errors are shown with a red background; hover for the message. Errors in one PWR net never stop the computation of the others.

Common problems

SymptomLikely cause and fix
Excel import fails with E_XL_HEADER_NOT_FOUNDA required column is missing or named unexpectedly, or the header is below row 20. The message lists the missing columns. Rename the headers as shown on the stack-up, PWR or decap page. The Conductivity column must exist even if only copper rows are filled.
A layer shows Type "Metal" that should be a dielectricIts Conductivity cell contains a number. Clear it (or write 0).
|Z| keeps rising towards low frequencyExpected: no voltage regulator is modelled, so the curve is capacitive at the low end. Add bulk capacitors as decap rows if you want to see their effect.
The decap seems to have no effect / huge |Z|Check the model: 1F is 1 femtofarad, 1M is 1 milliohm/millihenry. Look at the C @100 kHz and SRF columns and use Preview model. For .s2p files check the S2P mode (series vs shunt).
Results look identical after an editThe plot title says "(inputs changed)": results are not recomputed automatically. Press F5. Also check that the edited row is Enabled and assigned to the right PWR name (case-sensitive).
A plot tab has a red iconThat PWR failed. Filter the Messages dock by its source PWR:name; typical causes are a missing model file or wrong layer numbers.
Marker readout shows "n/a"The marker frequency is outside the sweep range. Widen f start / f stop.
VDD on deep planes is much worse than expectedThe via loop length is the depth of the nearer plane; planes deep in the stack give long, inductive vias. Check h_near and L_loop in the Vias tab; consider more vias per decap pad or a smaller via pitch.
Strong peaks near 1 GHzPlane resonances of the synthetic plane (W × 1.4·D_ref). Their frequency is indicative only; see synthetic geometry.
Computation is slowLarge planes with small drills need many cavity modes (status bar shows the count); many decaps increase the port count. Reduce the number of sweep points for exploration, or split very large decap rows.
E_SINGULARUsually overlapping ports (W_PORT_OVERLAP) combined with ideal zero-impedance models, or zero-length vias. Separate row distances, give models a small ESR/ESL, check layer numbers.
Yellow banner "Another Simple PI Calculator window owns the auto-save"A second instance is running. Close it, or use Save As in this window. See auto-save.
Program starts with an empty project after a crashLook for W_AUTOSAVE_RECOVERED_BACKUP / W_AUTOSAVE_CORRUPT in the Messages dock; damaged files are kept in the auto-save folder (File ▸ Show Auto-save Folder).
Model file not found after moving a projectRelative model paths are resolved from the Excel file folder, the project folder and the Model search folder. Set the Model search folder in Vias ▸ Advanced, or fix the paths.

Log file

Unexpected program errors are listed in the Messages dock as E_INTERNAL (the program keeps running and your inputs stay auto-saved); an unexpected error while computing one PWR net is reported as E_PWR_INTERNAL for that net only. The technical details are written to a log file in the auto-save folder (File ▸ Show Auto-save Folder):

Windows:  %APPDATA%\SimplePICalculator\logs\app.log
Linux:    ~/.local/share/SimplePICalculator/logs/app.log

When reporting a problem, include this file, the project (File ▸ Save As) and the model/Excel files it uses.
