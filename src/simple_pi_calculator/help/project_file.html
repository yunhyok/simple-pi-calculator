Projects and auto-save

Simple PI Calculator never asks you to save before closing: everything is auto-saved continuously and restored at the next start. Named project files (*.spical.json) are an additional, explicit way to keep versions of a design or to share it.

Auto-save

What is saved

All inputs (stack-up table, via settings, PWR and decap tables, sweep, unit) and the session: window size and position, splitter and dock layout, selected tabs, decap filter, zoom of each plot, recent files, the associated named project and whether it has unsaved changes. Computed curves are not stored; if results were shown when you closed the program, the computation runs again automatically at the next start.

When it is saved

  • About 1 second after the last change (every edit, import, tab switch, zoom, window move restarts the timer);
  • immediately when a computation finishes, before New/Open, after Save/Save As, and when the window is closed.

Unchanged states are not rewritten. The file is written safely: first to a temporary file, then the previous auto-save is kept as a backup, then the new file replaces it. A crash or power loss therefore never leaves you without a readable state.

Recovery at start-up

  1. The auto-save is read. Missing model or Excel files and invalid values are not corruption: the state is restored and the problems are shown in the Messages dock as usual.
  2. If the file is damaged (not valid JSON, wrong structure), it is moved aside and the backup is used (W_AUTOSAVE_RECOVERED_BACKUP). If the backup is damaged too, the program starts with defaults (W_AUTOSAVE_CORRUPT, with the paths of the moved files so you can inspect them).
  3. If the file was written by a newer version of the program, it is moved aside and the backup or defaults are used (W_AUTOSAVE_NEWER).

No dialog interrupts the start; messages appear in the Messages dock and the status bar.

Two windows at the same time

Only the first running instance auto-saves. A second instance shows a yellow banner "Another Simple PI Calculator window owns the auto-save…", starts with defaults and never overwrites the auto-save – use File ▸ Save As there to keep your work. If the program crashed, the stale lock is detected and removed automatically.

Command-line options: --no-restore starts with defaults (the next change overwrites the auto-save, after keeping the old one as backup); --self-test runs a headless check of the installation.

The .spical.json project file

A UTF-8 JSON text file that you can read, diff and keep under version control. It contains all inputs, including the imported tables, so a project opens even if the Excel files have moved; the source paths are kept for Re-import. Paths are stored relative to the project file when on the same drive (otherwise absolute), with forward slashes. Named project files never contain window/session data.

KeyContent
formatAlways "simple-pi-calculator-project".
schema_versionFile format version (currently 2).
app_versionProgram version that wrote the file.
stackupsource_path and layers[] with number, name, thickness_mm, conductivity_s_per_m, dk, df (null for empty).
viasdrill_diameter_mm (0.2), antipad_diameter_mm (0.5), via_pitch_mm (1.0), vias_per_pad (1, parallel vias on each decap pad), pad_via_count (1).
advancedvia_model ("pair"), plating_thickness_mm (0.025), via_conductivity_s_per_m (5.8e7), mounting_inductance_nh (0), s2p_default_mode ("series"), model_search_dir (null).
pwrsource_path and rows[] with name, pwr_layer, gnd_layer, width_mm, enabled. The height is never stored (derived).
decapssource_path and rows[] with pwr_name, model_file, count, distance_mm, dummy, subckt, s2p_mode, enabled.
sweepf_start_hz (1e5), f_stop_hz (1e9), n_points (400), show_plane_only (false).
displayz_unit: "ohm", "mohm" (default) or "uohm".
sessionOnly in the auto-save file (window and plot state); ignored with an info message if found in a named file.

Missing optional keys take their defaults; unknown keys are ignored with W_PROJECT_UNKNOWN_KEY.

File format versions

  • Adding new optional settings does not change schema_version; older program versions ignore them.
  • When a later version changes the meaning of existing keys, schema_version increases and older files are converted automatically when opened (I_PROJECT_MIGRATED). The project is marked modified; the file on disk is untouched until you save, and on that first save the original is kept as <name>.schema<n>.bak.spical.json.
  • Schema 1 → 2: vias.vias_per_decap (PWR + GND vias of one decap via set, e.g. 2) was replaced by vias.vias_per_pad (vias on each decap pad) = vias_per_decap / 2, rounded up (2 → 1, 4 → 2). Results are unchanged.
  • A file written by a newer program version cannot be opened (E_PROJECT_NEWER); update the program.
